# Баг-репорти: Гурман-Інфо

Середовище прогону: https://gourmet-info.netlify.app/ · Playwright 1.64 · Chromium 156 / WebKit 27.2 (Linux, headless) · 2026-10-30.

## BUG-001 · Закрито: не баг (форма працює)
| | |
|---|---|
| **Статус** | Closed / Not a bug, підтверджено TC-034 (2026-10-30) |
| **Пов'язані кейси** | TC-033 (авто), TC-034 (ручний) |
| **Компонент** | Форма `pairing-request`, секція `#contact` |

**Початкова гіпотеза:** у розгорнутому HTML на `<form>` немає `data-netlify="true"`, тому заявки можуть не доходити.

**Результат перевірки:** реальна заявка від 2026-10-30 з'явилась у Netlify → Forms → `pairing-request`. Панель також показує, що ввімкнено захист через honeypot.

**Чому гіпотеза була хибною:** під час деплою Netlify обробляє HTML: прибирає `data-netlify` і додає hidden `form-name`. Тому відсутність атрибута на проді є нормою, а наявність hidden `form-name` якраз свідчить, що форму зареєстровано.

**Висновок для тестування:** перевіряти дійсний результат (запис у Forms), а не внутрішній атрибут. TC-033 тепер перевіряє `name` форми й hidden `form-name`.

## BUG-002 · Ім'я з одних пробілів проходить валідацію
| | |
|---|---|
| **Severity / Priority** | Low / Medium |
| **Пов'язані кейси** | TC-027 (авто, xfail) |

**Кроки**
1. У поле «Ім'я» ввести 3 пробіли; email `olena@example.com`.
2. Натиснути «Отримати підбір пари».

**Фактично:** запит відправляється з `name='   '`. HTML5 `required` + `minlength=2` не обрізають пробіли.

**Очікувано:** форма відхиляє порожнє за змістом ім'я з підказкою.

**Рекомендація:** `pattern="\S.*\S"` на полі `name` або перевірка `value.trim().length >= 2` на клієнті (і на сервері, якщо з'явиться).

## BUG-003 · Немає захисту від подвійної відправки
| | |
|---|---|
| **Severity / Priority** | Low / Low |
| **Пов'язані кейси** | TC-036 (авто, xfail non-strict) |

**Кроки:** заповнити форму коректно → швидко двічі клікнути «Отримати підбір пари».

**Фактично:** WebKit відправив 2 POST. У Chromium результат залежить від таймінгу (1 запит). У CI 2026-10-30 дубль відтворився лише у Firefox, тобто баг плаваючий.

**Очікувано:** один запит; кнопка блокується після першого кліку.

**Рекомендація:** невеликий JS-обробник `submit`, що ставить `button.disabled = true` на час відправки.
