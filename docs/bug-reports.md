## BUG-001 · Форма не оголошена для Netlify Forms (потребує підтвердження)
| | |
|---|---|
| **Severity / Priority** | High / High (**гіпотеза**, доки не виконано TC-034) |
| **Пов'язані кейси** | TC-033 (авто, xfail), TC-034 (ручний) |
| **Компонент** | Форма `pairing-request`, секція `#contact` |

**Кроки**
1. Відкрити https://gourmet-info.netlify.app/ → DevTools → Elements.
2. Знайти `<form name="pairing-request" method="post">`.

**Фактично:** у тегу `<form>` немає `data-netlify="true"` (або `netlify`) і немає `action`. Є лише hidden `form-name` та honeypot `bot-field`. Коментар у коді (`data-netlify: обробка форми хостингом Netlify`) говорить, що атрибут мав би бути.

**Очікувано:** `<form name="pairing-request" method="POST" data-netlify="true" data-netlify-honeypot="bot-field">`. Без цього Netlify не реєструє форму під час деплою.

**Ризик:** заявки користувачів можуть не доходити, а POST на сервер повертати 404. Це головна цільова дія лендингу.

**Як підтвердити (1 хвилина):** відправити форму з даними `QA Test / qa@example.com`; перевірити, що з'явилась сторінка підтвердження (не 404) і запис у Netlify → Forms. *Автотести реальних відправок не роблять.*

**Рекомендація:** додати атрибути, перерозгорнути сайт, додати `data-netlify-honeypot="bot-field"` та сторінку подяки (`action="/dyakuyemo.html"`).

## BUG-002 · Ім'я з одних пробілів проходить валідацію
| | |
|---|---|
| **Severity / Priority** | Low / Medium |
| **Пов'язані кейси** | TC-027 (авто, xfail) |

**Кроки**
1. У поле «Ім'я» ввести 3 пробіли; email `olena@example.com`.
2. Натиснути «Отримати підбір пари».

**Фактично:** запит відправляється з `name='   '`. HTML5 `required` + `minlength=2` не обрізають пробіли.

**Очікувано:** форма відхиляє порожнє за змістом ім'я з підказкою.

**Рекомендація:** `pattern="\S.*\S"` на полі `name` або перевірка `value.trim().length >= 2` на клієнті (і на сервері, якщо з'явиться).

## BUG-003 · Немає захисту від подвійної відправки
| | |
|---|---|
| **Severity / Priority** | Low / Low |
| **Пов'язані кейси** | TC-036 (авто, xfail non-strict) |

**Кроки:** заповнити форму коректно → швидко двічі клікнути «Отримати підбір пари».

**Фактично:** WebKit відправив 2 POST. У Chromium результат залежить від таймінгу (1 запит).

**Очікувано:** один запит; кнопка блокується після першого кліку.

**Рекомендація:** невеликий JS-обробник `submit`, що ставить `button.disabled = true` на час відправки.
